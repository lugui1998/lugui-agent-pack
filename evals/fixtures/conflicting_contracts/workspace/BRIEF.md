# Protocol migration brief

Migrate the client request adapter for deployment to gateway 2.3. Read the protected target facts first, then obtain protocol evidence. The target accepts only the JSON envelope defined by the acceptance checker and rejects the flat draft. Do not browse or alter these synthetic packets.

The parent has capacity for one active child. Start one `docs_researcher` with only `source_v1.json` plus the target identity (gateway 2.3), then after it returns start a second `docs_researcher` with only `source_v2.json` plus the target identity (gateway 2.3). Ask each to independently interpret its draft and return the wire-format recommendation it supports for target 2.3, with its scope and caveats; do not ask either child to invent a position or claim access to the other draft. The parent retains the target acceptance facts for reconciliation. The drafts intentionally conflict. Prioritize this prerequisite evidence before optional presentation work. Capture the first failed `python check_migration.py .` result from the known-bad initial implementation. After actual conflicting recommendations and the failed check, make one planner handoff carrying both evidence packets and the failure for acceptance-plan verification; decisive checker evidence may resolve the conflict without any further escalation. If actual returned recommendations do not conflict, record that limitation and do not fabricate disagreement or force a handoff. Once resolved, the root agent implements the adapter.

Required files: `MIGRATION_PLAN.json`, `migration.py`, `EVAL_REPORT.md`. Optional lower-priority deliverable: `PRESENTATION.md`, with exactly three short sections (`Decision`, `Evidence`, `Validation`) and no more than 12 lines; the parent may create it while the second child runs, only after prerequisite evidence work has been launched. The plan must contain `selected_protocol`, `target_gateway`, `required_capability`, exact `source_scopes`, structured `acceptance_shape`, `disagreement_resolution`, and `validation_command` equal to `python check_migration.py .`. The adapter must expose `encode_request(request_id, payload)` and return `{"protocol":"v2","request_id":request_id,"body":payload}`. Preserve request id and payload exactly. The report must state both draft scopes, the selected behavior, the failed-check observation, and any limitation. Runtime events are graded externally; do not fabricate transcripts, child ids, timestamps, or routing records.


Plan serialization: `selected_protocol` may be `v2` or `v2_envelope`. `source_scopes` may map each source filename to `gateway 2.3` (or `target gateway 2.3`), or contain two records with `source` and `target_identity` fields. Records may retain evidence and caveats. `acceptance_shape` must match `accepted_shape` in the protected target facts. These equivalent representations do not change the required wire behavior.
